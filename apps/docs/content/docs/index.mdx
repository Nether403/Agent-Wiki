# Machine-First Design Agent Wiki

Welcome to the **Design Agent Wiki**, the first design engineering platform engineered from the ground up for **AI developer agents** (Claude Code, Cursor, Codex, v0).

## Why Machine-First?

Modern frontend engineering is undergoing a tectonic shift: developer agents are becoming the primary consumers and assemblers of code primitives, while human engineers focus on visual curation, high-level architecture, and quality assurance.

Traditional component libraries were designed for human visual browsing—relying on heavy DOM payloads, extensive explanatory prose, and visual trial-and-error. When an AI agent is forced to build interfaces from generic training weights or unstructured documentation, it inevitably produces **"AI Slop"**:
- Hallucinated component props and nonexistent imports.
- Chained type assertions (`as any as ComponentProps`).
- Arbitrary, non-token spacing overrides (`p-[17px]`, `mt-[13px]`).
- Banned visual clichés (the indigo-600 button, the purple-to-blue linear gradient, decorative emoji grids, and blanket glassmorphism).
- Catastrophic accessibility failures (unlabeled icons, missing ARIA bindings, unhandled keyboard navigation).

## Double-Exposure Architecture

The Design Agent Wiki solves this by implementing a dual-interface model:
1. **Human Interface**: Aesthetic Next.js + Tailwind v4 documentation with interactive playgrounds, theme toggles, and live sandboxes.
2. **Machine Interface**: Ultra-lean, token-efficient programmatic endpoints designed specifically for LLM context windows:
   - `/llms.txt`: Flat discovery index summarizing categories, components, and taste dials.
   - `/llms-full.txt`: Complete flat markdown specification with embedded TypeScript source.
   - `/raw/components/[slug]`: Clean, token-efficient Markdown representations with structured YAML frontmatter and verified TSX source.
   - `/r/[name].json`: Programmatic endpoint adhering to the shadcn v3 registry schema.
   - `/r/registry.json`: Master index of all registered items for rapid agent discovery.
   - `/SKILL.md`: Public endpoint exposing the canonical agent execution contract and active taste dials.
   - `@design-wiki/mcp`: Official Model Context Protocol server exposing `search_library` / `search_components`, `fetch_raw_markup`, `get_installation_schema`, and `audit_code_slop` (< 15KB payloads).

## Platform Modules

- **`apps/docs`**: Next.js 15 App Router documentation and double-exposure static registry host (`/raw/` for agents, HTML for humans).
- **`packages/registry`**: **45 curated zero-slop components** across all 7 taxonomy categories (`ui:primitive`, `ui:motion`, `ui:creative`, `ui:editorial`, `ui:block`, `ui:media`, `ui:utility`) with dynamic static compiler (`build-registry.ts`).
- **`packages/harvester`**: AST static analysis engine, Directed Acyclic Graph (DAG) dependency analyzer (`dependency-graph.ts`), repository shallow cloner, dial scorer, and automated anti-slop review gate.
- **`packages/mcp-server`**: Model Context Protocol server deployable as a local stdio process or a high-performance Cloudflare Worker edge service with embedded snapshot catalog (0ms disk access), SSE streaming, and sub-15KB payload budget.
- **`packages/audit-linter`**: 21-rule AST + regex anti-slop linter, standalone dial classifier, and Taste Dial consistency auditor (`taste-dial-audit.ts`) scoring **100/100** across the full catalog.
- **`scripts/test-a11y-linter.ts`**: Automated WCAG 2.1 AA CI linter. Validates keyboard navigability, WAI-ARIA roles, and motion fallbacks across all 45 registry components (`pnpm test:a11y`).
- **`scripts/sync-rulepacks.ts`**: Multi-agent rulepack synchronizer that distributes `SKILL.md` rules into 11 agent ecosystem configurations (Claude Code, Cursor, Windsurf, Copilot, Codex, OpenClaw, Hermes, Pi, AGENTS.md, Antigravity) (`pnpm sync:rules`).
- **`scripts/test-agent-ecosystem.ts`**: Automated compatibility test suite verifying 100% ecosystem rule adherence across all 11 platforms (`pnpm test:agents`).
