# Registry Compilation & Packaging

The **Registry Compiler** (`@design-wiki/registry/compiler/build-registry.ts`) dynamically sweeps component source directories, analyzes dependencies, escapes source files into JSON strings, and generates production registry endpoints.

## Compilation Pipeline

```
[packages/registry/src/ & /components] 
               │
               ▼
   [Dynamic Directory Sweeper]
               │
               ▼
    [AST Dependency Extractor]
  (Extracts peer & registry dependencies)
               │
               ▼
     [Schema Item Serializer]
    (Escapes JSX/TSX source into JSON)
               │
               ▼
┌──────────────────────────────┴──────────────────────────────┐
▼                                                             ▼
/r/[name].json & /r/registry.json                             /llms.txt & /llms-full.txt
(shadcn v3 CLI installation schemas)                          (Agent discovery manifests)
```

## Features

### 1. Dynamic Asset Sweeper
Recursively scans `packages/registry/src/` across all 7 taxonomy category subdirectories: `primitives`, `motion`, `creative`, `editorial`, `blocks`, `media`, and `utility`. Across 29 confirmed components, if a component lacks manual metadata overrides in `COMPONENT_OVERRIDES`, the compiler dynamically infers titles, descriptions, categories, taste dials, and tags using the Harvester AST engine with `KNOWN_REPOSITORIES` preset support.

### 2. Dependency Auto-Mapping
Peer npm dependencies are automatically identified from AST import specifiers:
- `motion/react`, `framer-motion` → `motion`
- `lucide-react` → `lucide-react`
- `three` → `three`
- `@radix-ui/react-*` → `@radix-ui/react-*` (auto-bound to `registryDependencies`)
- `@ark-ui/react` → `@ark-ui/react` (auto-bound to `registryDependencies`)
- `clsx`, `tailwind-merge`, `class-variance-authority` → appended to `dependencies`
- `@/components/ui/[primitive]` → appended to `registryDependencies`

### 3. Schema Conformance
Every generated JSON item complies with `registry-item-schema.json` (extending the shadcn v3 registry item schema).

### 4. Output Artifacts

| Destination | Format | Description |
| :--- | :--- | :--- |
| `apps/docs/public/r/[name].json` | JSON | Component installation schema consumed by `npx design-wiki add` and `npx shadcn add` |
| `apps/docs/public/r/registry.json` | JSON | Master index of all 29 registered components with taxonomy and taste dials |
| `apps/docs/public/raw/components/[name].md` | Markdown | Machine-first component documentation with structured YAML frontmatter and verified TSX source |
| `apps/docs/public/llms.txt` | Plain Text | Flat machine discovery index summarizing components, taxonomy, and dials |
| `apps/docs/public/llms-full.txt` | Markdown | Complete flat context payload with embedded component code |

#### Raw Proxy Route & `.md` Extension Transparency

The `/raw/[...slug]` Next.js route (`apps/docs/app/raw/[...slug]/route.ts`) transparently strips the `.md` extension from incoming request slugs. This means both `/raw/components/button` and `/raw/components/button.md` resolve to the same resource, allowing agents and curl requests to use either format without error.

## Running the Compiler

```bash
# Compile all registry artifacts, JSON schemas, raw markdown, and llms.txt
pnpm build:registry
```

## Installing Components via CLI

Consumers can install any compiled registry item directly:

```bash
# Native Design Wiki installer (automatically detects path aliases & peer packages)
npx design-wiki add <component-name>

# Traditional shadcn v3 installer
npx shadcn@latest add http://localhost:3000/r/<component-name>.json
```
